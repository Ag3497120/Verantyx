# セキュリティ設計 / Security model

公開リポジトリとして配布しても安全であるための規約。2026-08-12 の監査で確立。

## 資格情報は同梱しない

- このリポジトリ・アプリバンドルに **トークン/鍵は一切含まれない**(監査済み:
  検知に掛かるのはアプリ自身の秘密検知正規表現・HFライブラリの公開テスト用
  文字列・ダミー値のみ)。
- HuggingFace への公開 (`verantyx.release`) は**実行者自身の** `hf auth login`
  資格で動く。トークンを持たない人が同じコードを動かしても、公開はできず
  提案(Issue)しかできない — これが利便性と安全の両立点:
  **能力はコードでなく資格に付く。**

## 権限の三層

| 層 | 誰でも | 必要資格 |
|---|---|---|
| 提案 | GitHub Issue (vera-suggest) を立てる | GitHubアカウントのみ |
| 取り込み | `release` / `grow` を実行 | リポジトリのwrite権 |
| モデル公開 | HF リポジトリ更新 | kofdai のHFトークン |

エージェント(Vera-a)は**起案のみ**。Issue の投稿・モデル公開は人間の操作。

## LAN 面

- `JGenAgentServer` の非 `/pipe/*` ルートはループバック限定。
- `/pipe/model/*`(重みの転送)は**ペアリングで合意した session id が必須**
  (403 otherwise)。/pipe/hello 等の発見系は名乗りのみで、データを持たない。

## モデル配布

- 構造世代ごとに HF リポジトリを分離(`kofdai/vera-alpha` = A,
  `kofdai/vera-b` = B, …)。マイナー(知識のみ)更新は同一リポジトリの
  コミットとして積む — コミット履歴=チェックポイント履歴。
