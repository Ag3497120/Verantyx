# 事前登録 4 — ファッション埋め込みは候補を出せるか、事実を出せるか

登録日: 2026-08-23（**実行前に書いた**）

## 何を決めるための実験か

いま類似検索に使っているのは Apple の `VNGenerateImageFeaturePrint` で、
これはファッション用に作られたものではありません。`Marqo/marqo-fashionSigLIP`
はファッション画像で fine-tune された対照学習の埋め込みモデル（Apache-2.0、
ViT-B-16-SigLIP webli から派生）です。

外部の助言は「Qwen を置き換えるのではなく併用せよ」でした。方向としては
妥当に見えます。ただし**その助言は測定に基づいていません。** ここで測ります。

決めたいのは二つです。

1. **入れ替えるべきか。** この道具が実際にやる仕事（同じ服が別のコマ・別の
   角度で写っているものを引き当てる）で、Apple の指紋より本当に良いのか。
2. **点数を何に使ってよいか。** 対照モデルは必ず順位を返します。
   **「分からない」を返せません。** すると 0.91 という数字が「ウールである」
   と読まれる危険が、生成モデルの捏造と同じ形で戻ってきます。

二つ目のほうが製品として重要です。台帳は
OBSERVED / CONTESTED / INFERRED / PROPOSED / UNKNOWN で出来ていて、
**類似度は観測ではありません。**

## 測るもの

### VE1 — 同じ服を、別の見えから引き当てる

DeepFashion In-shop（`Marqo/deepfashion-inshop`）から、3 枚以上の見えを持つ
品番を N 件。問い合わせは 1 枚、書庫は残り全部。同じ `item_ID` なら正解。

比較するのは三つ:

- (a) Marqo-FashionSigLIP の画像側
- (b) 素の ViT-B-16-SigLIP (webli) — **fine-tune の効果を分離するため**
- (c) Apple `VNGenerateImageFeaturePrint` — いま使っているもの

指標は Recall@1 / Recall@5 / MRR。ばらつきは品番単位のブートストラップ
（2000 回）で 95% 区間を出します。

**反証: Marqo が Apple を上回る差が 95% 区間に 0 を含むなら、入れ替えません。**
「専用モデルだから良いはず」は理由になりません。

### VE2 — 素材の順位は、置き直しに耐えるか

各画像に対し、固定した素材文の一覧を順位付けします
（wool / cashmere / cotton / linen / denim / leather / silk / polyester の coat）。

そのうえで、**素材の情報を持ち去らない変換**をかけます:

- 中央 90% 切り出し
- 左右反転
- 明るさ ±15%
- JPEG 品質 40

服の素材は、切り出しても反転しても変わりません。だから 1 位が入れ替わったら、
その順位は素材を見ていたのではありません。

**予測を先に書きます: 1 位の入れ替わりは 5% 未満に収まらない。**
**もし 5% を超えたら、素材の順位は自動採用してよい対象から外します。**
（これは既に台帳で使っている置き直し不変の門を、埋め込みモデルに当てるだけです）

### VE3 — 「分からない」が点数に出るか

三種類の入力で、1 位と 2 位の差（margin）と 1 位の素点の分布を比べます:

- (i) 実写の服
- (ii) この道具が作った**線画**（材質は原理的に写っていない）
- (iii) 一様乱数の画像

**予測: (ii) と (iii) の margin は (i) の分布の中に入り、区別が付かない。**
これが当たれば、**点数は確度として画面に出せません。** 外れれば、
閾値による棄権が作れます。どちらでも次にやることが決まります。

### VE4 — それは素材を見ているのか、色を見ているのか

灰色化（色を落とす）で 1 位がどれだけ入れ替わるか。
色は素材の情報を**部分的にしか**持たないので、ここは VE2 とは別に扱います。
大きく入れ替わるなら、「素材」の順位は相当が色の順位です。

### VE5 — 速さと大きさ

1 枚あたりの時間（Apple 指紋と比較）、重みのバイト数、常駐メモリ。
27B の生成モデルを類似検索のたびに呼ぶより軽い、という主張の実測。

## やらないこと

- モデルカードのベンチマークの再現はしません。**あれは既に公表されていて、
  この道具の問いではありません。**
- 素材の正解ラベル付きデータで「素材当て精度」は測りません。手元に権利の
  はっきりした素材ラベル付きコーパスが無いからです。**無い測定を、
  あるかのように書かないため**、VE2/VE3/VE4 は正解を必要としない
  不変性の検査だけで組んであります。

## 権利について

`Marqo/marqo-fashionSigLIP` はモデルカード上 Apache-2.0（2026-08-23 確認）。
DeepFashion 系のデータは**評価にだけ使い、製品には同梱しません。**
元データの利用条件は別途確認が要ります — モデルが Apache-2.0 であることは、
学習データの権利が自由であることを意味しません。

## この実験で変わりうる実装

- 通れば: 類似検索の裏側を差し替える（画面の意味は変えない）
- VE2/VE3 の予測が当たれば: **類似度を台帳に入れる口を作らない。**
  候補は PROPOSED 席にしか置けず、採用は人の手に限る。

---

## 実測 2026-08-23

評価集合: DeepFashion In-shop から **実写 990 枚 / 220 着**（1 着あたり平均
4.5 の見え: front / side / back / additional / full / flat）。**評価専用。**

まず道具を確かめた。**VE0: 自前の L2 が Apple の `computeDistance` と
最大差 6.0e-8 で一致。** ここが合っていなければ以降は全部指標の取り違えになる。

### VE1 — 同じ服を別の見えから引き当てる（990 問）

| | Recall@1 | Recall@5 | MRR |
|---|---|---|---|
| Marqo-FashionSigLIP | **0.658** | **0.880** | **0.755** |
| 素の ViT-B-16-SigLIP (webli) | 0.571 | 0.863 | 0.697 |
| Apple `VNGenerateImageFeaturePrint`（現行） | 0.341 | 0.605 | 0.463 |

品番単位のブートストラップ（2000 回）:

- Marqo − Apple: **ΔMRR +0.292、95% 区間 [0.264, 0.322]**（0 を含まない）
- Marqo − 素の SigLIP: **ΔMRR +0.058、95% 区間 [0.041, 0.076]**（0 を含まない）

**反証は起きなかった。入れ替える。**
二つ目の行が重要で、差は「SigLIP が Apple より強い」だけではなく、
**ファッション向けの fine-tune 自体が上乗せしている**。両方を測らなければ
これは分けられなかった。

### VE2 — 素材の順位は置き直しに耐えない（予測どおり落ちた）

1 位が入れ替わった割合（素材の情報を持ち去らない変換、200 枚）:

| 変換 | 1位の入れ替わり |
|---|---|
| JPEG 品質 40 | **15.0%** |
| 中央 90% 切り出し | 10.0% |
| 明るさ +15% | 9.0% |
| 左右反転 | 8.5% |
| 明るさ −15% | 6.5% |

**左右反転で服の素材は変わらない。それでも 8.5% で 1 位が入れ替わる。**
事前に書いた線は 5%。全部の変換がそれを超えた。

→ **素材の順位は証拠にならない。** 台帳へ自動で入れる口は作らない。

### VE3 — 点数に「分からない」は出ない（予測どおり）

1 位と 2 位の差（margin）:

| 入力 | margin 平均 | 実写の 5–95% 帯に入る割合 |
|---|---|---|
| 実写の服（200 枚） | 0.0200 | — （帯そのもの: 0.0012–0.0469） |
| この道具が描いた線画（8 枚） | 0.0020 | 62.5% |
| **一様乱数の画像（32 枚）** | 0.0151 | **100%** |

**乱数の画像に「ウール 1 位」と付く margin が、実写 200 枚の分布に完全に
収まる。** つまり点数の大きさは「見えているか」を一切区別しない。

→ 類似度を確度として画面に出せない。閾値で棄権も作れない。

### VE4 — 色を落としても 16.5%

灰色化での 1 位入れ替わりは 16.5% で、JPEG 再圧縮の 15.0% とほぼ同じ。
「素材の順位＝色の順位」という単純な話ではなく、**そもそも不安定**。

### VE5 — 速さ

| | 1 枚あたり |
|---|---|
| Apple `VNGenerateImageFeaturePrint` | 4.4 ms |
| Marqo-FashionSigLIP（CPU） | 67.2 ms |

**15 倍遅い。** そして **MPS が使えない** — torch 2.8.0 / macOS 26.5 のこの
機体では SigLIP の attention pooling が Metal の assertion でプロセスごと
落ちる（batch=1 でも再現）。速さの数字はこの制約込み。
27B の生成モデルを類似検索のたびに呼ぶよりは、桁で軽い。

## 結論

1. **画像側は入れ替える。** 精度差は大きく、区間も 0 を跨がない。
2. **文字側（素材の順位）は台帳に繋がない。** VE2 と VE3 が、これを
   「観測」として扱えないことを別々の角度から示している。
   置ける席は PROPOSED まで、採用は人の手に限る。
3. 速さと MPS の件があるので、**重みは同梱せず、利用者が登録した
   モデルを engine 側で呼ぶ**形にする。無ければ
   `UNKNOWN_MODEL_NOT_INSTALLED` と閉じ方を返す。

## 測っていないこと（書いておく）

- 映画・アニメのコマでの精度は測っていない。評価集合は EC の商品写真。
  **見えの条件がまるで違うので、この数字をそのまま持ち込めない。**
- 素材当ての正解率は測っていない（権利のはっきりした素材ラベル付き
  コーパスが手元に無い）。VE2/VE3/VE4 は正解を必要としない不変性の検査。
