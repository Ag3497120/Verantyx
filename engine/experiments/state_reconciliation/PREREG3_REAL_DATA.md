# 事前登録13: 実データでの状態突合(茨城県・避難施設)

日付: 2026-08-22。**この文書を確定してから測る。** 合成治具(PREREG 5/5)を
実在のオープンデータで確かめ直す。

## 素材(取得のみネット、エンジンはオフライン)

* 出所A **国の集約**: 指定緊急避難場所データ 茨城県 GeoJSON(1,992件)
  — この一覧に載っている = 指定が有効、と読む
* 出所B **県の集約**: 茨城県 避難施設情報 CSV(2,380行)
  — 列「指定緊急避難場所(0:対応無し 1:対応 9:不明)」を読む

同じ施設を二つの組織が別々に公開しており、**食い違いは仕込まない**。
在るものを数える。

## 対応付け

施設名を正規化(前後空白・全角空白・括弧内注記を落とす)し、**同一市区町村
コード内**で突き合わせる。名寄せできなかったものは「対応なし」として
別に数える — 名寄せの失敗を食い違いに数えない。

## 測ること(R1〜R5)

R1. **食い違いの検出**: Bが `0:対応無し` と言い、Aが載せている施設を
    `有効:有効` と `有効:無効` の両極として置き、`deep_report` が
    `contested` を返すか。件数を報告する
R2. **9:不明を食い違いに数えない**: Bが `9` の施設は極を持たないので
    争いにならないこと(不明は否定ではない)
R3. **不在の型**: 片方にしか無い施設は「矛盾なし」ではなく
    `unknown_not_held` になること(PREREG2で入れた区別が実データで効くか)
R4. **規模**: 店のバイト数が施設数に比例し、報告行数に比例しないこと
R5. **出典**: 各食い違いに、どちらを誰が言ったかが付くこと

## 停止条件

* 名寄せの取りこぼしを食い違いとして数えていたら、その分を除いて測り直す
* R2 が破れたら(不明を否定として扱っていたら)この用途ごと再設計

## 予想を書かない

件数は測ってから書く。**0件でも記録する** — 実データが綺麗だったという
事実も結果である。
