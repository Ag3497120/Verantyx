# 事前登録14: 服飾台帳 — 服を作る装置ではなく、何が確定しているかを持つ装置

日付: 2026-08-22。**この文書を確定してから作る。**

## 何を作るか

映像や写真から服を**生成しない**。「いま何がどこまで分かっているか」を
型で持ち、**縫製師に渡せる指示書**にする。裁断は取り返しがつかないので、
埋めた推測を確定として渡さないことが全て。

## 四つの状態(混ぜない)

* `OBSERVED`   複数の観測が一致した(出典に時刻・カットを持つ)
* `INFERRED`   構造から推した(観測ではない。根拠を明記)
* `PROPOSED`   外(画像検索・視覚モデル・人の提案)から来た。**未採用**
* `UNKNOWN_NOT_OBSERVED` 見えていない。**閉じ方**を添える

**モデルの自己申告(0.71 等)は事実の欄に入れない。**出典の一部として
運ぶだけ。この装置が出せる確度は「独立した観測が何本一致したか」であって、
モデルが自分に付けた点数ではない。

## 保証(G1〜G5)

G1. **採用は人の行為**。`PROPOSED` は指示書の確定欄に出ない。採用して
    初めて `OBSERVED`(出典: 誰が採用したか)になる
G2. **観測が食い違ったら確定にしない** — `CONTESTED` として両論を出典つきで
    出す(片方を勝たせない)
G3. **未観測は「無し」ではない**。「ポケット無し」と「ポケットは見えていない」
    を別の値で返す(不在と否定を混ぜない)
G4. 指示書には**確定・推論・未確定**が別の節で出る。混ぜて出さない
G5. 未確定の一覧が**そのまま作業指示**になる(何をすれば閉じるか)

## 測定(V53〜V57)

- V53 提案は確定に混ざらない。採用して初めて入る
- V54 観測の食い違いが CONTESTED として両論出典つきで出る
- V55 「無し」と「未観測」が別の値
- V56 指示書の三節が混ざらない(確定欄に推論・提案が1件も出ない)
- V57 未確定一覧に閉じ方が必ず付く

## 展開(4面)

新しい枠は作らない。既存の `field_app` と同じ形 —
**127.0.0.1 の HTTP + ブラウザ**で Mac / Windows / Web を同時に賄い、
`--lan` で電話からも読める。iPhone の**ネイティブ**は別事業として分ける
(engine を iOS に載せる話になり、この一日では終わらない)。

## 停止条件

* 確定欄に提案や推論が1件でも出たら棄却(この装置の存在理由が消える)
* 確度を数字で出し始めたら棄却
