## #1 Default README.md is Japanese, not English (README-en.md is a separate file)

作成: 2026-07-31T03:30:50Z

- Make `README-en.md`'s content the default `README.md`, move the Japanese version to `README-ja.md`

## #6 No timeout on Agent.run() -> JGEN backend calls

作成: 2026-07-31T03:31:16Z

The ReAct loop's `self.llm(prompt, system)` call (Vera-alpha's `agent.py`) has no timeout when the backend is a JGEN model served via the IDE's `JGenAgentServer`. If that call ever hangs (see the related 0%-CPU hang report), the entire chat turn is stuck forever with no recovery path visible to the user beyond force-quitting. Should have a bounded timeout with a typed error surfaced back to the ReAct loop.

## #7 ReAct loop resends the full conversation history every step (no cross-step caching)

作成: 2026-07-31T03:31:17Z

Each step of `Agent.run()`'s ReAct loop sends the ENTIRE accumulated history (task + all prior tool calls/observations) as a fresh prompt to the LLM. There's no cross-step KV-cache reuse -- every step is effectively a full prefill of an ever-growing prompt. For large local models (e.g. 12B+) and long analysis tasks, this makes later steps progressively slower, and likely contributes to hitting `max_steps_reached` before real work completes. Worth investigating whether the underlying JGEN engine's KV cache could be reused/extended across ReAct steps within one turn instead of restarting from scratch each time.

## #8 Add regression test for forced-synthesis salvage (max_steps_reached fallback)

作成: 2026-07-31T03:31:38Z

Fixed in Vera-alpha (Ag3497120/Verantyx-Vera-alpha@07c20a6): the forced-synthesis fallback used to discard real findings when the model's answer wasn't strict `{"final": ...}` JSON, silently returning a bare `max_steps_reached` error even when the model had a real, useful answer. Now salvages raw text as `final` when JSON parsing fails but the LLM call itself succeeded. Verified manually offline; should be added as a permanent regression test in CI so this can't silently regress again.

## #17 P5 hidden-state reflection: ROLE_LAYER_HINTS layer assignment is an unvalidated guess

作成: 2026-07-31T03:32:20Z

`cognitive_interventions.py`'s `ROLE_LAYER_HINTS` (goal→layer 2, evidence→4, rejected_hypothesis→6, knowledge_gap→8) was a hand-picked heuristic, documented in the code itself as never validated against real model behavior. Real measurement against a loaded Qwen-0.5B model confirmed this directly: decoding these shallow/mid layers via `lm_head` produced near-max-entropy noise regardless of injection. A systematic sweep across layers (especially closer to the final layer) and across different model sizes/architectures is needed to find where reflection actually produces coherent, on-topic output.

## #18 P5 reflection: no alpha value found yet that's both different-from-baseline AND coherent

作成: 2026-07-31T03:32:21Z

Follow-up to the injection-vector norm-matching fix (Ag3497120/verantyx-cli@1c62c828c, which fixed outright residual corruption). Real measurement against Qwen-0.5B post-fix: at the shipped alpha (0.12), the final-layer decode stayed IDENTICAL to baseline (no visible effect); at alpha 0.1-0.2 it degraded back to an empty/degenerate token. A middle ground that's both clearly different from baseline and still a coherent, on-topic token hasn't been found yet for this model/prompt combination -- open empirical tuning work, not a known bug.

## #19 Inconsistent text-to-vector embedding convention: cognitive_interventions.py vs EternalMemoryStore

作成: 2026-07-31T03:32:22Z

`EternalMemoryStore.embed()` wraps text in a PromptEOL-style prompt (`This sentence: "{text}" means in one word:"`) before encoding, a known trick for getting a single-vector representation that's actually meaningful. `cognitive_interventions.py`'s intervention-vector construction (via `jgen_reflect`) just calls `encode()` directly on the raw text label with no such wrapping. Worth checking whether applying the same PromptEOL convention improves the interpretability of P5's injected vectors.

## #21 arc_env_adapter.py's coarse-graining thresholds are unvalidated, and no real ARC-AGI-3 data is wired in yet

作成: 2026-07-31T03:32:37Z

`_bucket()`'s thresholds (0 / 1-3 / 4-9 / 10+ changed cells) for canonicalizing grid-transition diffs were picked as a reasonable starting point, not measured against real ARC-AGI-3 task data (which doesn't exist in this codebase yet -- only synthetic test grids were used to verify the mechanism works at all). Needs (1) a real ARC-AGI-3 task loader and (2) threshold tuning once real transition data is available.
